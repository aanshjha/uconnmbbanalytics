## Reconciled Data

The 32 games already represented in the repository were fetched from ESPN's summary endpoint. Original JSON, retrieval timestamp, source URL, and SHA-256 are cached under `_data/00_source/espn/`. Header final scores are cross-checked against box-score arithmetic and every scoring event. Ten event statistics (points, FGA/FGM, FTA/FTM, 3PA/3PM, offensive/defensive rebounds, turnovers), for both teams in every game, match all **640** box-score comparisons.

Canonical products:

- `_data/02_derived_inputs/reconciled_games.csv`: 32 games, source dates/sites, final scores, box totals and separate reconciliation flags.
- `_data/02_derived_inputs/reconciled_events.csv`: 14,589 unique source plays, including substitutions, fouls, rebounds, and other events omitted from the earlier shot/turnover table.
- `_outputs/00_qc/reconciliation_summary.json`: coverage, checks, code/output hashes and release status.
- `_outputs/00_qc/source_stat_reconciliation.csv`: each event-to-box comparison.
- `_outputs/00_qc/duplicate_manual_events.csv`: duplicated IDs and all originating paths.
- `_outputs/00_qc/manual_source_differences.csv`: event-level comparison; zero differences after normalizing text whitespace.
- `_outputs/00_qc/source_event_issues.csv`: mismatches in the feed's intermediate scoreboard fields.
- `_outputs/00_qc/core_stint_reconciliation.csv`: game-level stint audit and exclusion reasons.

The raw folders contain 6,637 event rows but only 5,605 unique event IDs: 1,032 redundant copies across `_conf`, `_nc`, and `_bet`. Of those, 536 were in the `_conf`/`_nc` folders used by the previous loader. For example, Florida's old 154–146 report doubled the actual [77–73 final](https://www.espn.com/mens-college-basketball/game/_/gameId/401812793/uconn-florida). The new canonical stream is rebuilt from source, not generated by halving totals. Source IDs remain strings so 18-digit play IDs cannot be rounded into collisions.

Game ordering uses period and game clock, with source sequence as a tie-breaker: delayed entry can put an earlier event after the end of the game in sequence-number order. Even then, 15 games have inconsistent intermediate scoreboard fields. Those raw values and issues are preserved. Their final scoring-event sums and box totals reconcile; this does not certify every intermediate score or same-clock event order. The pilot uses conservative event sequences and does not use those scoreboard fields to establish possession outcomes.

## Withheld Lineup Results

Only 24 of 32 source-covered games have matching core-stint point totals. Eight differ; two additional exhibition games have no matching source snapshot in this coverage. The stint files lack a verified event-to-stint mapping, and previous repair code manufactured possessions from points or a default of one. A dry-run audit identifies 106 of 838 stint rows with those historical fills. The repaired helper marks these for source repair and requires a backup before any rewrite. Game-total agreement alone does not establish correct lineup attribution or possession boundaries.

Run `python3 _scripts/ops/audit_lineup_evidence.py` to rebuild a separate source-evidence inventory under `_outputs/09_lineup_source_audit/`. It preserves the original stints. Across the 32 covered games, every final point is accounted for by the 14,589 source events: 3,761 of 4,545 points have a source-consistent tracked five-player state; 784 points at substitution clocks are excluded from lineup attribution. Three same-clock substitution chains that initially appeared contradictory resolve when their source order is applied; their transition evidence is saved separately, while all events at those clocks remain excluded. No substitution group remains invalid in the current snapshots. The audit yields 1,133 bounded control sequences and excludes 1,072 candidates; these are incomplete possession coverage, so their count is not a model denominator. Every source scoring event falls within at least one recorded stint clock interval, but 48 stint rows have point totals outside even the source-event clock-boundary allowance. Missing source-event clock coverage is ruled out; whether the old interval, boundary assignment, or point entry is wrong remains unresolved. The historical 106-fill count is available only when private repair reports are present; a fresh checkout reports it as unknown.

The event inventory is diagnostic evidence, not a replacement lineup table. Fifteen games have intermediate source-score timeline issues even though event sums and final box scores reconcile. Exact same-clock order, all possession endings, and full lineup scoring coverage remain unresolved. No lineup model has been refit or released from this audit.

All legacy lineup/player recommendations remain unreleased. The shared R bootstrap guards direct historical analysis, model fitting, pipeline, and batch entrypoints before they write new recommendation outputs; the historical website exporter also stops. The read-only Shiny view remains available with a historical warning. Original outputs are retained and locally marked as unvalidated; the existing hosted website has not been republished and should not be presented as current validated results.

Releasing lineup results requires source-linked possession boundaries, verified five-player states through substitutions and halftime, reconciliation of both teams' points and game coverage, explicit exclusions for unresolved sequences, and a new rolling lineup evaluation. Unresolved records are not filled with plausible-looking values.

## Corrected Evaluation

See [evaluation protocol](PREGAME_EVALUATION.md) and `_outputs/08_reconciled_evaluation/pregame_evaluation.md`. The target is opponent final points, not points per possession or lineup impact. Five prior games provide warmup; 27 subsequent games are each tested once. Every prediction uses earlier dates only, train-only features/scaling, a fixed model specification, and the same held-out games as both baselines.

| Method | MAE in points | RMSE in points |
|---|---:|---:|
| Expanding mean | 8.599 | 12.621 |
| Last-three mean | 11.309 | 14.327 |
| Pregame ridge | 8.679 | 12.907 |

The ridge model does not beat the expanding mean. This small retrospective evaluation does not support a model advantage over that baseline. Source snapshots were retrieved now; prior final scores are treated as knowable before later game dates, but original historical feed vintages are unavailable. No calibrated probabilities, lineup effectiveness, or staff time savings are established.

## Staff Review Pilot

The default report is `_outputs/08_staff_pilot/401812793/defensive_review.html`, with supporting Markdown, source-linked possession evidence, and a baseline packet. It asks staff to review a few bounded sequences from UConn–Florida, not to change rotations based on inferred blame. No coverage labels or film-confirmed errors are invented.

The measurement commands and protocol are in [staff pilot guide](STAFF_PILOT.md). Computer generation time is recorded separately from staff time. The project user has volunteered for a trial: Butler home (`401822868`) is assigned to the baseline condition and DePaul home (`401822893`) to the report condition. Both are reconciled home games with 60 opponent points; game difficulty and order remain confounders. The preassigned conditions and task are saved in `_outputs/08_staff_pilot/trial_assignment.json`. Actual starts and completions are recorded in `_outputs/08_staff_pilot/human_sessions.jsonl`; consult its generated summary for measured results. Human sessions must be timed and entered using the provided workflow before any utility claim is made.
